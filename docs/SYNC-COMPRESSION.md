# Lossless cloud snapshot compression (27.1.68)

Cloud progress snapshots are encoded as a JSON envelope (`format: ekab-sync-gzip-v1`, `data: base64(gzip(UTF-8 JSON))`). The envelope is used only when smaller than plain JSON. Native CompressionStream/DecompressionStream provide gzip without a third-party CDN or paid service. PDFs keep their original bytes and hashes; PDF quality is unchanged.

A fresh device discovers the same private per-device snapshot names, decodes the envelope, then validates owner, schema, fields and causal clocks before merging. Plain snapshots remain readable. No local state, export format or merge semantics changed. Compressed and decompressed input have 20 MB limits; corrupted archives are rejected before applying data. Browsers without decompression support show a request to update, retaining local data. Old running app versions reject the envelope in schema validation; refresh all devices after this update. Existing plain snapshots are replaced gradually after the next change and successful upload, retaining the previous revision.

`node scripts/verify-sync-codec.mjs` checks independent serialization/restoration, Greek/emoji text, causal metadata, old plain JSON, corruption, expansion limits and unsupported browsers. The synthetic fixture (200 questions, 30 dated reviews each, short Greek notes) measured 579,825 bytes plain versus 9,132 bytes packed, about 98% smaller. This is a repetitive test fixture, not a measured average for real users, and does not forecast PDF compression or a fixed increase in user capacity.
