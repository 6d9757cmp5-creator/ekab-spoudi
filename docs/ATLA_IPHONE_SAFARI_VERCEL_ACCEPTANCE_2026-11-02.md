# ATLA — Πραγματικό iPhone Safari & Vercel preview release gates
**2 Νοεμβρίου 2026 · PR #151 (stacked on #148 → #147)**

## Κανόνας
Αυτά είναι δύο ανεξάρτητα κριτήρια αποδοχής, όχι πρόσθετες δυνατότητες.
Απαγορεύεται να δηλωθεί «100%» χωρίς πραγματική δοκιμή iPhone Safari **της ίδιας έκδοσης του PR #151** και επιτυχημένο Vercel preview για αυτό το commit. Browser WebKit σε Linux δεν αποδεικνύει πραγματικό iOS.

## Gate A — Vercel preview για το συγκεκριμένο PR
1. Ελέγχουμε το **τελευταίο commit** του PR #151 και το Vercel status για **αυτό το SHA**.
2. Αν δείχνει `build-rate-limit`, δεν κάνουμε παράκαμψη, ανεξέλεγκτα retriggers, αλλαγή πακέτου ή οικονομική αναβάθμιση. Ο κάτοχος του Vercel project ελέγχει **Deployments → αποτυχημένο build → logs** και **Usage/Billing → build/deployment limits**.
3. Με διαθέσιμο όριο/εγκριμένη πρόσβαση Vercel, μία ελεγχόμενη επανεκτέλεση **μόνο** της preview ανάπτυξης για το SHA. Δεν γίνεται production deploy.
4. Επαληθεύουμε την URL προεπισκόπησης, ότι αντιστοιχεί στο **συγκεκριμένο SHA**, ανοίγει `/paramedic.html`, οι υποδιαδρομές φορτώνουν και οι ενημερωμένοι έλεγχοι CI περνούν. Κρατάμε preview URL και screenshot/log ως τεκμήρια.
5. Ένα πράσινο GitHub Actions job **δεν υποκαθιστά** την επιτυχία Vercel.

**Κατάσταση 02/11:** το GitHub status στο SHA `1bcc24255208367645283cfa9b2be39e4e47f894` δήλωνε Vercel failure με `upgradeToPro=build-rate-limit`. Δεν αποδίδουμε με βεβαιότητα το όριο στον χρήστη ή στην ομάδα χωρίς να ανοίξουμε το αντίστοιχο Vercel project.

## Gate B — πραγματικό iPhone / iOS Safari
**Προϋπόθεση:** υπάρχει επιβεβαιωμένο preview από το Gate A, ώστε το πραγματικό iPhone να δοκιμάζει την νέα αλλαγή, όχι την παλιά παραγωγή.

**Καταγραφή πριν τη δοκιμή:** μοντέλο συσκευής, έκδοση iOS, πραγματικός Safari, ημερομηνία, preview URL, αναγνωριστικό Git commit. Δεν ζητούνται δεδομένα λογαριασμού/μαθητή ή κλινικά δεδομένα.

**Βήματα πραγματικής δοκιμής (5 ξεχωριστά pass/fail):**

- [ ] **1 — Είσοδος/οθόνη:** Safari → preview `paramedic.html`· η σελίδα χωρά στο πλάτος της οθόνης (portrait/landscape), links ΣΑΕΚ και ΕΟΠΠΕΠ λειτουργούν, καμία κενή οθόνη ή απρόσμενο scroll.
- [ ] **2 — Στοχευμένο ECG:** `saek-course-02.html#lesson-7` → «Θέλω να εξασκηθώ» → υπάρχον `mentor-ecg.html`. Εμφανίζεται **συνθετική κυματομορφή**, όχι διάγνωση· «Επιστροφή» γυρίζει ακριβώς στο κεφάλαιο.
- [ ] **3 — 3D καρδιά:** `saek-course-01.html#lesson-10` → προαιρετικό anatomy viewer `mode=organs&system=cardiac&focus=heart`. Περιμένουμε το πραγματικό μοντέλο, αγγίζουμε/περιστρέφουμε, επιβεβαιώνουμε εστίαση καρδιάς και ασφαλή επιστροφή στο κεφάλαιο. Η προσομοίωση SwiftShader σε Chromium **δεν αρκεί**.
- [ ] **4 — ΕΟΠΠΕΠ χωρίς διαρροή εξέτασης:** `theory.html?question=EOP-A-070` στο reader → προαιρετική άσκηση ECG· `EOP-A-071` δεν προσφέρει άσχετο ECG. Στην ενεργή εξέταση δεν υπάρχει βοηθητική απάντηση ούτε η προαιρετική πρόταση. Καμία διαγραφή προόδου.
- [ ] **5 — Μόνο επιλεγμένο offline υλικό:** αφού προβληθεί επιλεγμένη ερώτηση/απάντηση και εκπαιδευτική εικόνα, **Safari offline** → κείμενο και προεβλημένη εικόνα από προσωρινή αποθήκευση. Το 3D/ECG παραμένει online-only, χωρίς ψευδές fallback. Μην αποθηκεύετε ταυτόχρονα γιγαντιαίους 3D άτλαντες.

**Αποδεικτικό:** screenshot ή σύντομη εγγραφή οθόνης από το πραγματικό iPhone + συνοπτικό pass/fail των πέντε βημάτων, χωρίς στοιχεία μαθητή. Αποτυχημένα βήματα παραμένουν εκκρεμή και οδηγούν σε στοχευμένες διορθώσεις/επανέλεγχο.
