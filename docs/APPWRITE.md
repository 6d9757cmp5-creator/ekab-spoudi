## Ενημέρωση 27.1.36 — Google χωρίς εξάρτηση από cookies τρίτων

Στις 26/10/2026 ο ιδιοκτήτης ολοκλήρωσε το OAuth Web client στο Google Cloud και
καταχώρισε τα στοιχεία στο Appwrite Console. Ο πάροχος εμφανίζεται ως Google enabled,
με Browser sign-in ενεργό και Native sign-in ανενεργό. Το Appwrite εμφανίζεται Free.
Το client secret μένει αποκλειστικά στο Console και δεν προστέθηκε στον κώδικα.

Το κουμπί «Σύνδεση» στην κορυφή ανοίγει τον λογαριασμό. Η «Συνέχεια με Google»
χρησιμοποιεί Account.createOAuth2Token με σταθερά success/failure URLs στην ίδια
εγκατάσταση GitHub Pages, χωρίς πρόσθετα Google scopes. Το oauth-callback.html καταναλώνει
το εφάπαξ userId/secret μέσω Account.createSession και επιβεβαιώνει Account.get() πριν
επιστρέψει στην αρχική. Η URL καθαρίζεται πριν από οποιοδήποτε αίτημα συνεδρίας,
ο callback έχει no-referrer και δεν αποθηκεύεται από τον service worker. Δεν αποθηκεύουμε
το εφάπαξ secret χειροκίνητα: τη συνεδρία διαχειρίζεται ο επίσημος Web SDK με το δικό
του cookie fallback. Υπάρχει αποσύνδεση χωρίς διαγραφή τοπικής προόδου.

Η σημαία googleLogin είναι true. Η σημαία sync παραμένει false μέχρι να δημιουργηθούν
και να δοκιμαστούν οι ιδιωτικοί πόροι που περιγράφονται παρακάτω. Η ενεργοποίηση του
παρόχου και οι έλεγχοι URL δεν αποδεικνύουν ολοκληρωμένο login χρήστη· απαιτείται
πραγματική είσοδος, επιστροφή και logout στον browser.

Έλεγχοι χωρίς πραγματικά credentials ή πρόσβαση σε λογαριασμό:
node --experimental-vm-modules scripts/verify-account.mjs και verify-appwrite.mjs.

## Τι λειτουργεί σε αυτή την έκδοση

Η εφαρμογή παραμένει HTML/CSS/JavaScript στο GitHub Pages, χωρίς React ή build step.
Το `updates.js` φορτώνει ανεξάρτητα το `appwrite-client.js` στις 31 υπάρχουσες σελίδες που χρησιμοποιούν τις κοινές ενημερώσεις. Οι παλιές ανακατευθύνσεις και η σελίδα επισκευής δεν αλλάζουν.
Ο κοινός client χρησιμοποιεί endpoint `https://fra.cloud.appwrite.io/v1` και project
`6ade83ec00260198ae34` (EKAB Spoudi). Αυτά είναι δημόσια αναγνωριστικά, όχι secrets.
Ο επίσημος Web SDK 29.1.0 βρίσκεται τοπικά στο `vendor/` και στην offline cache.

Γίνεται ένα `client.ping()` ανά φόρτωση εγγράφου, ακόμη και αν κληθεί ξανά το
`startAppwrite()`. Χωρίς δίκτυο παραλείπεται, χωρίς αυτόματες επαναλήψεις.
Μετά από 8 δευτερόλεπτα αναμονής εμφανίζεται αποτυχία επιβεβαίωσης· το υποκείμενο
αίτημα μπορεί να ολοκληρωθεί αργότερα, χωρίς δεύτερο αίτημα ή αλλαγή της κατάστασης.
Το ping επιβεβαιώνει μόνο τη συνδεσιμότητα, όχι OAuth, πρόσβαση σε δεδομένα ή συγχρονισμό.
Η κατάσταση εμφανίζεται στο παράθυρο λογαριασμού από το κουμπί «Σύνδεση».
Είναι επίσης διαθέσιμη ως export `connectionStatus` και event `ekab:appwrite-status`.

Δεν δημιουργείται ανώνυμο session. Η ροή Google ξεκινά μόνο από τον χρήστη. Δεν διαβάζεται η τοπική πρόοδος από τον νέο κώδικα και
δεν ανεβαίνουν σημειώσεις/PDF/ρυθμίσεις. Το `cloudFeatures.googleLogin` είναι `true` και το `cloudFeatures.sync` παραμένει `false`.

## Platform και δωρεάν πρόγραμμα

Στο Appwrite Console → EKAB Spoudi → Platforms, χρειάζεται Web platform με hostname
`6d9757cmp5-creator.github.io` (χωρίς https ή /ekab-spoudi). Για ανάπτυξη πρόσθεσε
ξεχωριστά `localhost` ή `127.0.0.1` μόνο εφόσον χρησιμοποιούνται.
Το HTTP ping ελέγχθηκε με Origin του GitHub Pages: HTTP 200, `Pong!`, επιτρεπόμενο Origin.
Απαιτείται επιπλέον πραγματικός έλεγχος browser μετά τη δημοσίευση.

Μόνο **Free**: καμία αναβάθμιση, κάρτα, Pro, πρόσθετος επί πληρωμή πόρος ή πληρωμένο
compute. Ο client δεν μπορεί να αλλάξει το πρόγραμμα ή να επιβεβαιώσει τη χρέωση
του οργανισμού. Το πραγματικό Free plan πρέπει να επιβεβαιωθεί στο Console· δεν
συμπεραίνεται από επιτυχές ping. Σύμφωνα με την επίσημη τιμολόγηση, στο όριο του Free
το project παγώνει αντί να χρεώνει υπέρβαση. Τότε διατηρούμε τοπική λειτουργία,
αφαιρούμε περιττά cloud δεδομένα ή περιμένουμε επαναφορά ορίων, χωρίς αναβάθμιση.
Οι τρέχουσες ποσοστώσεις ελέγχονται στο Console πριν ενεργοποιηθεί συγχρονισμός PDF.

Στις 26/10/2026 ελέγχθηκε το υπάρχον Console του EKAB Spoudi: εμφανίζει **Free**

## Σύνδεση Google (δεν έχει ενεργοποιηθεί ή δοκιμαστεί end-to-end)

1. Δημιουργία Google OAuth Web client. Το client secret μένει αποκλειστικά στο
   Appwrite Console → Auth → Google, ποτέ στο repository ή στον browser.
2. Καταχώριση στο Google του ακριβούς redirect URI που δείχνει το Appwrite Console.
   Καταχώριση μόνο επιτρεπόμενων success/failure URLs της εφαρμογής, με το
   `/ekab-spoudi/` για GitHub Pages. Όχι αυθαίρετο redirect από παραμέτρους URL.
3. Προσθήκη Account SDK module και login μόνο μετά από ενέργεια του χρήστη.
   Έλεγχοι login, ακύρωσης, logout, ληγμένου session και Safari/mobile cookies.
4. Καμία ανώνυμη session κατά την εκκίνηση και καμία αποθήκευση OAuth token χειροκίνητα.

## Συγχρονισμός όλων: απογραφή και σύμβαση πριν την υλοποίηση

| Πεδίο | Υπάρχουσα τοπική πηγή | Μελλοντικός ιδιωτικός πόρος |
| --- | --- | --- |
| ΕΟΠΠΕΠ, αυτοαξιολόγηση, πρόχειρες σημειώσεις | localStorage `ekab-eoppep-official-v15`, πεδίο `draft` ανά ερώτηση | Εγγραφές ανά χρήστη/ερώτηση με schema version |
| ΣΑΕΚ, ολοκλήρωση κεφαλαίων | `ekab.saek.read.v1.<μάθημα>.<κεφάλαιο>` | Εγγραφές χρήστη/μαθήματος/κεφαλαίου |
| Θέση ανάγνωσης ΣΑΕΚ | `ekab.saek.lastchapter.<μάθημα>` | Ρυθμίσεις ανά χρήστη |
| Θέμα εμφάνισης | `ekab.theme.v1` | Ρυθμίσεις ανά χρήστη |
| Προσωπικά PDF και μεταδεδομένα | IndexedDB `ekab-personal-pdf-v1`, store `documents`: id, name, semester, course, created, blob | Ιδιωτικό Storage bucket + εγγραφές μεταδεδομένων |
| Τοπικό αντίγραφο προόδου | IndexedDB `ekab-spoudi-private-backups`, store `snapshots` | Παραμένει τοπικό μέσο ανάκτησης |

Το υπάρχον JSON export v22 καλύπτει ΕΟΠΠΕΠ/ολοκλήρωση ΣΑΕΚ, **όχι** PDF ή όλες τις
ρυθμίσεις. Δεν πρέπει να παρουσιαστεί ως πλήρες cloud backup. Ανεξάρτητες νέες
σημειώσεις χρειάζονται επιπλέον σχήμα· σήμερα υπάρχουν τα πρόχειρα `draft` ΕΟΠΠΕΠ.

Πριν ενεργοποιηθεί το `sync`:

- Δημιουργία database/tables και bucket εντός Free, με έλεγχο ποσοστώσεων και μεγέθους
  αρχείων. Το τοπικό όριο PDF 50 MB δεν εγγυάται ότι επιτρέπεται αντίστοιχο cloud upload.
- Row/document security και file security. Πρόσβαση read/update/delete μόνο στον
  αντίστοιχο `Role.user(userId)`· δημιουργία μόνο για συνδεδεμένο χρήστη. Κανένα
  δημόσιο read/write ή γενικό update/delete σε όλους τους συνδεδεμένους χρήστες.
  Το `ownerId` από μόνο του δεν αποτελεί κανόνα πρόσβασης.
- Δοκιμές δύο λογαριασμών και επισκέπτη για αποτροπή ανάγνωσης/αλλαγής/διαγραφής
  ξένων εγγραφών και αρχείων. Απαιτούνται πραγματικά tests δικαιωμάτων backend.
- Ρητή επιλογή αρχικής εισαγωγής τοπικών δεδομένων μετά το login. Ποτέ κενό cloud
  snapshot πάνω στην υπάρχουσα πρόοδο, ούτε αυτόματη εισαγωγή σε διαφορετικό λογαριασμό.
- Εκδόσεις εγγραφών, timestamps, ανίχνευση συγκρούσεων, tombstones για διαγραφές,
  ουρά offline αλλαγών, ελεγχόμενες επαναλήψεις και χειρισμός ορίων/αποτυχίας upload.
- Δοκιμή δύο συσκευών για κάθε πεδίο, offline επανασύνδεση, σύγκρουση σημειώσεων,
  διαγραφή/ακύρωση PDF, logout και αλλαγή λογαριασμού με άθικτο τοπικό αντίγραφο.

Μέχρι να ολοκληρωθούν αυτά, η εφαρμογή δηλώνει μόνο «επιτυχής σύνδεση» και
**όχι** «συνδεδεμένος με Google», «συγχρονισμένο» ή «αποθηκευμένο στο cloud».
