# Educational Animation ENGINE — Dell preparation

This is preparation tooling for the existing ENGINE contract in `../../docs/educational-animation-engine/README.md`. It does not implement a new content engine, MENTOR, scientific approval, automated analysis, narration, rendering or publishing.

## Installed runtime and commands

Use `./worker.ps1 doctor` from PowerShell in this directory. The launcher uses the isolated official Node 24.22.2 LTS runtime at `%LOCALAPPDATA%\EKABAnimationWorker\node-v24.22.2-win-x64`, sets `VIDEO_GENERATION_ENABLED=false` and limits the Node heap to 2048 MiB. Existing global Node is preserved. For another machine, install the matching Node 24 LTS from nodejs.org, verify its release SHA256 and update the local launcher path if the patch changes. `npm ci --ignore-scripts` restores exact dependencies from the committed lockfile; it is not an activation step. `.env.example` is documentation, not automatically loaded. No credentials are required.

Commands:

- `./worker.ps1 doctor`: actual Node, Git, FFmpeg, Remotion and sampled CPU/RAM/disk status.
- `./worker.ps1 check` and `./worker.ps1 test`: syntax and non-rendering safety tests.
- `./worker.ps1 browser-check`: Remotion Chromium startup and shutdown only, no composition, still or video frames.
- `./worker.ps1 app-check`: application HTTP/body load at mobile and desktop viewports using installed Edge; external requests, media and POSTs blocked. This is not full clinical, MENTOR 3D or real-phone acceptance.
- `./worker.ps1 prepare -InputPath C:\path\to\review-draft`: checksum-verified snapshot under ignored `.local/bundles/v1-<manifest-sha256>`. Never put this output inside input. No uploads.
- `./worker.ps1 verify -InputPath C:\path\to\bundle`: hashes, file inventory, identity and metadata checks.
- `./worker.ps1 route -InputPath C:\path\to\workload.json`: routing estimate only.

`render`, `ai`, `tts`, `dispatch` and `publish` are rejected. Even `VIDEO_GENERATION_ENABLED=true` is an error. Remotion is a dependency, not an active job service; do not bypass the worker using direct rendering commands. No auto-start, Windows service, scheduled task or runner is installed.

## Preparation input contract

Provide UTF-8 JSON files `source.json`, `script.json`, `storyboard.json`, `scenes.json`, `assets.json`, `workload.json`. Script and storyboard are supplied drafts, not generated by the worker. Structured analysis/extraction and AI adapters remain future work. Do not place credentials, personal data or existing approved publications in input folders. Dotfiles, symlinks and credential-like filenames are rejected; content-based secret detection is not implemented.

- `source.json`: `sourceId`, `version`, `sourceHash` (64 lowercase hex characters). This records the upstream source hash; the worker cannot independently establish clinical correctness or authenticity of that upstream source.
- `script.json`, `storyboard.json`: valid JSON supplied by the reviewer; pedagogical completeness is not inferred from syntax.
- `scenes.json`: `{ "scenes": [{ "id": "scene-id", "conceptIds": ["concept-id"] }] }`. Coverage still needs explicit human review.
- `assets.json`: `{ "assets": [] }`, or entries with unique `id`, relative `path` under `assets/`, `sha256`, `provenance`, `license`, `version`, `attribution`, `videoDerivativeRightsConfirmed: true`. Actual bytes must match. Rights metadata is a recorded assertion, not a new license approval system.
- `workload.json`: positive numbers `width`, `height`, `durationSeconds`, `sceneCount`, `memoryGiB`, and booleans `has3d`, `requiresGpu`. Scene count must match. Unknown/GPU-heavy jobs cannot be silently downgraded.

Prepared manifests contain all input hashes, source identity, Node version, exact dependency versions, lockfile SHA256 and expected MP4 format with `created:false`. Every bundle is `prepared-unapproved`, with clinical and coverage approval false. Its content-addressed ID detects edits; this is integrity, not a cryptographic signature or proof of authorization. Treat bundle directories as immutable; verify again after every transfer. Large binaries stay out of git. Asset input limits: 256 MiB/file, 512 MiB/bundle, 500 files. Larger bundles require a separately designed streaming preparation path.

## Resource policy

One preparation process per checkout, exclusive lock, no waiting backlog (queue depth one includes active work); a second invocation fails. A stale lock after a crash requires inspecting its recorded PID/time before manual removal. Before copying, sample CPU over 500 ms and require load <=75%, >=3 GiB free RAM and >=20 GiB disk. Resource pressure declines the job; it does not launch a retry loop. Windows itself enforces no hard CPU quota here; these are admission checks, not VM resource guarantees. Future local rendering must retain concurrency 1 and benchmark 720p, <=30 seconds, <=12 scenes and <=2 GiB estimated job memory. 3D goes to remote CPU assessment; GPU workloads remain unconfigured.

## Hybrid architecture and isolation

The deployed Actions workflow is preparation validation only: manual/main-path triggers, read-only contents token, credentials not persisted, bounded concurrency, 10-minute timeout, no PR trigger, upload, render or schedule. It runs hosted Linux CPU checks. No heavy-render dispatch, artifact store or renderer is connected yet. Future trusted orchestrator must fetch a bundle by content ID, verify hashes, source/clinical approvals and explicit activation before any AI/TTS/render; use immutable artifacts with retention and trusted digest, read-only download credentials, no secrets in bundles, bounded retries and resource benchmarks. Standard hosted runners are not assumed to have GPUs. Existing unrelated workflows are preserved.

Do not register a runner on the personal Windows host. Windows 11 Home is not assumed to provide supported Hyper-V isolation. Before registration, provision a dedicated VM on a supported hypervisor or a separate worker machine, disposable guest snapshots, standard guest-only account, no host shares/clipboard/SSH agent/browser profiles, no personal credentials, bounded vCPU/RAM/disk and outbound network policy. Use ephemeral runner registration credentials and one job per disposable guest. Only trusted protected workflow revisions may target it; never execute untrusted public PR code. Use repository/environment access controls, read-only tokens by default and no public-fork secrets. A dedicated user account alone is not adequate isolation. Isolation and a teardown test must be verified before registration. Nothing is registered by this preparation.

Activation needs a separate explicit implementation/review after scientific cross-check, approved source corrections and clinical review. Neither changing an environment variable nor completing the audit automatically activates this worker.

The final environment uses Remotion/Renderer 4.0.539 directly, without CLI/Studio or a Zod override. CLI/Studio was removed after its pinned Zod dependency caused an audit finding; forcing a patched Zod caused an exact-version warning. Renderer-only dependencies eliminate that unused dependency tree. No bundler, Studio UI, render entry point or production composition is installed. These belong to the later explicitly activated rendering implementation. The npm command is named `bundle:prepare` to avoid npm's automatic `prepare` install lifecycle. Run `node bundle-check.mjs` under the worker LTS environment for a real temporary metadata-only bundle/checksum round trip; admission limits still apply and no media is created.
